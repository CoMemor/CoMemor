CoMemor Security & Threat Model

Transparent documentation of CoMemor v1.1.0 trust boundaries, non-executing command policy, secret redaction layers, and explicit heuristic limits.

Non-Execution Invariant: CoMemor has zero server-side command execution capability. verify_fix always returns executedByServer: false and requiresHostConfirmation: true. Allowlist policy validation is NOT an OS sandbox.

1. Trust Boundary & Execution Policy

CoMemor treats all repository logs, command outputs, and previously persisted records as untrusted input:

  • Policy Validation Only: verify_fix checks proposed commands against an allowlist of binaries, rejects shell metacharacters (; & | > < ` $(), prevents workspace path escapes, and attaches context-aware riskReasons (for example elevating npx remote execution to high risk and npm install lifecycle scripts to medium risk).
  • Dashboard Isolation: dashboard-bridge runs in a separate process bound exclusively to 127.0.0.1 and opens SQLite in read-only mode. Operator decisions recorded in approvals-resolved.jsonl are audit annotations only.

2. Dual-Layer Secret Redaction

Every field passes through redaction before fingerprinting or disk persistence:

  • Pattern Detection: Deterministic regex scrubbing for GitHub PATs, AWS/OpenAI/Anthropic keys, JWTs, PEM blocks, and URI basic-auth credentials.
  • Shannon Entropy Gating: Flags unlabelled high-entropy tokens (≥ 24 chars, H(X) ≥ 4.5 bits/char).
  • Honest Limitation: Redaction is heuristic and cannot guarantee coverage of interleaved whitespace or short truncated secrets. Review .agent-memory/records.jsonl before committing to public repositories.

3. Persisted-Retrieval Poisoning Defense

To mitigate indirect prompt injection stored inside build outputs:

  • Zero-width characters are stripped and Cyrillic/Greek homoglyphs are canonicalized before analysis.
  • Seven heuristic detectors flag authority overrides, fake LLM delimiters, data exfiltration vectors, and abnormally high imperative-verb density.
  • All returned records are escaped and wrapped inside explicit <untrusted_historical_memory> XML boundaries.

4. Honest Verification & Confidence Scoring

Wilson lower-bound scores in v1.1.0 are derived strictly from deduplicated outcome events stored in .agent-memory/verification-events.jsonl (5-minute idempotency window per record). Outcomes are visibly labelled host_reported or human_reported rather than claiming independent execution proof.
